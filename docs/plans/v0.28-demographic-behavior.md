# v0.28: Demographic behavior

Date: 2026-08-24

## Product objective

Let users ask transparent demographic counterfactual questions without presenting aggregate population data as observed individual voting behavior.

The product distinction is:

```text
Observed aggregate composition
            +
Explicit user-authored behavior assumption
            ↓
Deterministic counterfactual vote change
```

The composition is evidence. The turnout or preference setting is an assumption. The resulting election is a scenario, not a forecast.

## v0.28A: Evidence and model contract

Status: implemented

- Inventory the PA, MI, and WI runtime evidence.
- Freeze VAP, vintage, geography, crosswalk, coverage, and capability semantics.
- Preserve Pennsylvania direct VTD, Michigan mixed bridge, and Wisconsin reconstruction differences.
- Mark Wisconsin group composition unavailable.
- Prohibit CVAP, eligibility, individual-turnout, candidate-preference, and ecological-inference claims.
- Add deterministic serialization and fail-closed validation.
- Authorize no vote mutation and render no demographic behavior controls.

## v0.28B: Group-specific turnout

Status: implemented

- Add one explicit turnout-change assumption per admitted group.
- Apply only to units with admitted group composition and valid remaining VAP capacity.
- Allocate integer ballots deterministically while respecting unit capacity.
- Keep candidate allocation separate and explicit.
- Reconcile every added ballot at group, unit, county, state, and portfolio levels.
- Disable or explain unsupported Wisconsin group controls instead of substituting statewide composition.
- Add URL recipe compatibility and worker stale-response gates.

Implementation notes:

- Pennsylvania and Michigan expose five explicit group turnout settings from 0 to +10.0 points in the Turnout editor.
- Group additions run after the existing statewide turnout setting and compete only for documented remaining local VAP capacity.
- A fixed canonical group order resolves the rare case where multiple requests compete for the same final capacity. The order is visible in the editor and never depends on candidate results.
- Candidate allocation remains the existing independent Harris share of added ballots. Group composition is not used as candidate preference.
- Scenario URL schema 3 preserves every group setting. Schema 2 portfolios remain compatible and restore all group settings to zero.
- Wisconsin shows an explicit unavailable state and rejects nonzero group recipes because its current admitted artifact has no group-composition cells.

## v0.28C: Group-specific preference

Status: implemented

- Add candidate-complete user-authored preference assumptions.
- Require explicit shares that sum exactly to the admitted candidate vector.
- Apply preference only to newly added ballots created by that same group's turnout assumption.
- Leave certified ballots untouched because they have no observed demographic identity.
- Let groups without a custom vector inherit the visible shared Harris-Trump added-ballot split.
- Never infer preference from certified geographic correlations.
- Keep Stein, Oliver, and residual Other/write-in behavior explicit.

Implementation notes:

- Each custom vector contains Harris, Trump, Stein, Oliver, and residual Other/write-in and sums to exactly 100 percent.
- Integer candidate allocation reconciles exactly within every group and reporting unit.
- Scenario URL schema 4 persists candidate vectors while schemas 2 and 3 remain compatible.
- Wisconsin rejects custom demographic preference for the same evidence reason that it rejects group turnout.
- This operation is candidate choice for newly authored turnout, not a transfer of certified ballots.

## v0.28D: Contribution and sensitivity explanation

Status: implemented

- Explain which user assumption changed which candidate ledger.
- Rank county and reporting-unit consequences without claiming individual causation.
- Compare baseline, scenario, and local capacity.
- Expose clipping, unavailable coverage, and off-map effects.
- Add bounded sensitivity views only where the arithmetic is deterministic and fully labeled.

Implementation notes:

- The selected group exposes requested, realized, and capacity-clipped ballots plus its exact five-candidate ledger.
- County and local-unit rankings use the model's accepted per-unit contribution records and never claim individual causation.
- Sensitivity is the deterministic Harris-minus-Trump movement per 1,000 added group ballots from the authored vector. It is not a probability or forecast.
- The panel isolates the turnout operation at insertion time and discloses that later statewide preference and third-party exchange operations may move ballots again.

## Release boundary

v0.28 does not add survey calibration, voter-file inference, turnout prediction, probabilities, race calls, demographic microtargeting, backend profiles, or hidden defaults.
