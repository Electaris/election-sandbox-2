# v0.28B: Group-specific turnout

Date: 2026-08-25

## Outcome

The Swingometer can now ask where added turnout changes an election using explicit aggregate group assumptions in Pennsylvania and Michigan.

The Turnout editor exposes five independent increases from 0 to +10.0 points. The map and every downstream county, state, national popular-vote, Electoral College, contribution, shared-link, and Election Night endpoint consume the same deterministic result.

## What changed

- Added five-category group composition to eligible PA and MI behavior units.
- Allocated group additions through exact integer, capacity-bounded local arithmetic.
- Kept the existing statewide turnout setting and group settings on one shared local-capacity ledger.
- Kept candidate choice separate through the existing Harris share of added ballots.
- Added group requested, realized, population, and state-total audit values.
- Added scenario URL schema 3 and backward-compatible schema 2 decoding.
- Added PA and MI controls, explicit evidence language, a group-clear action, and a group-added ballot readout.
- Added an explicit Wisconsin unavailable state without inventing substitute composition.
- Preserved worker request ordering and stale-response rejection through the existing scenario runtime.

## Interpretation boundary

The controls use aggregate 2020 VAP composition to place a user-authored turnout assumption geographically. They do not measure how individual people voted, predict turnout, infer candidate preference, or create a 2024 eligible-voter estimate.

## Next

v0.28C will define candidate-complete group preference assumptions. It must specify whether the preference vector applies to added ballots, existing ballots, or both before any implementation begins.
