# v0.27B: Geographic third-party behavior

Date: 2026-08-23

v0.27B makes the third-party control spatial. Stein, Oliver, and residual Other exchanges now flow through a deterministic reporting-unit allocation based on the selected bucket's certified local support, local major-party capacity, and canonical unit identity.

The change preserves every ballot and all five candidate buckets at reporting-unit, county, and state level. A named third-party color appears only when that candidate genuinely has the local plurality. Residual Other uses a separate aggregate marker and is never described as one candidate.

## Visible behavior

- Stein pluralities use a light-to-dark green margin ramp.
- Oliver pluralities use a light-to-dark amber margin ramp.
- aggregate Other pluralities use a light-to-dark purple margin ramp.
- ties and incomplete named vectors are neutral or remain major-party results.
- reporting-unit, county, and state readouts name the actual plurality leader and the winner-over-runner-up margin.
- the map legend identifies every plurality category.
- Shift remains a Harris-versus-Trump comparison.
- state tiles follow the true five-bucket plurality; third-party state wins retain their EV instead of being reassigned to Harris or Trump.
- Path to 270 requirements compare the target candidate with the true current leader.
- Election Night state, county, and unit colors use only the currently reported five-candidate vector. Final named-candidate totals never leak into a partial count.

## Compatibility

New shared scenarios use `electaris-behavior-v2`. Frozen historical replay fixtures retain their original engine evidence and exact fingerprints through an explicit legacy allocation profile.
